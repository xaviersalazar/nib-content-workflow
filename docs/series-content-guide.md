**This doc only covers the content-authoring side** — what a Series needs from *this* repo's pipeline,
and the current state of the three built Series.

## The one-sentence version

A Series is a curated, ordered set of 8–15 existing (or newly written) facts that explores **one
specific, named subject** — not a theme, not a category — from as many different disciplines as
genuinely apply. Contrast with the two structures this repo already knows:

- **Category** organizes by broad subject area (`geography`, `history`) — permanent, hierarchical.
- **Collection** curates by a shared *theme/angle* (`happy-accidents.json`-style — "breakthroughs nobody
  meant to make") — the facts are independent examples of one idea, interchangeable in principle.
- **Series** curates by one shared *subject* (Socotra, Pompeii, Apollo 13) — every fact exists to
  explain a different facet of *that one thing specifically*. Swap the subject and the facts stop making
  sense — that's the test that separates a Series from a Collection.

# Curation rules (what to check before proposing a fact for a Series)

Carried over from the design spec, restated for a content-authoring context:

1. **8–15 facts minimum viable**, occasionally up to 20 for an unusually deep subject.
2. **At least 4 categories represented.** Below that, it's really just a Topic with extra steps — this
   is exactly what disqualified "Black Holes" as a candidate (see below): 10 facts existed, but 7 were
   pure `astronomy` restating the same "black holes are extreme" idea.
3. **No artificial connections.** A fact earns its place by explaining a *distinct* facet of the named
   subject, not by merely mentioning it. Don't pad a Series with a fact that's only tangentially
   "in the neighborhood" (e.g. a fact about a *different* volcano doesn't belong in a Krakatoa Series
   just because it's also a volcano).
4. **The subject must be specific and bounded** — a named place, object, person, event, or discovery.
   "Nature," "The Ocean," "Volcanoes" fail this test the same way they'd fail as a Category name.
5. **A Series subject must not already be a Category.** This is what disqualified "Coffee" (16 facts, 5
   categories — looked great on paper, but `coffee` is already a top-level Category, so using it as a
   Series subject would contradict the whole point of the feature).
6. **Every fact must still stand alone**, exactly like today — a Series fact can surface as anyone's
   daily fact, in search, or in a category browse, with zero Series context. No new authoring constraint
   here; this repo's existing quality bar already guarantees it.
7. **Don't let one topic/subject carry too much of a Series.** Even when a subject is genuinely
   multi-faceted (e.g. Pliny the Younger within the Pompeii Series), watch the proportion — if one
   person/topic is behind a third or more of a Series' facts, look for another facet-holder before
   shipping. (This is what trimmed Pompeii's Pliny-anchored facts from 3 to 2 during drafting.)

# `exports/series.json` — status and format

**As of 2026-07-30, this is a real pipeline file, not a draft.** It was `series.draft.json` while the
three Series below were being sourced and drafted; now that all three clear the 8-fact/4-category bar,
it's been renamed and is treated the way `collections.json` is treated: **hand-maintained, not
regenerated by `export-facts.ts`**, but a first-class export alongside it.

```json
{
  "id": "the-alien-island",
  "title": "The Alien Island",
  "subtitle": "Inside Socotra, one of the strangest ecosystems on Earth.",
  "icon": "leaf",
  "factIds": ["socotra-endemic-plants", "..."]
}
```

Same shape as a `Collection` (see `content-schema-reference.md`) — `id`, `title`, `subtitle`, `icon`,
`factIds`, optional `addedAt` — because it's a straight match for `Nib/Models/Series.swift`.

**A Series is the one content type that routinely mixes old and new facts in the same set** — the case
`content-schema-reference.md`'s reveal-gate section calls out specifically. If a Series introduces
brand-new facts alongside ones already in the library, set `addedAt` on the Series **and** on only the
newly-drafted facts (their own `facts.json` entries) — leave the pre-existing facts it also pulls in
untouched. A fact does not inherit hidden/visible state from the Series (or category) it's in; each
gates on its own `addedAt`.

**IMPORTANT CORRECTION (2026-07-30, later same day):** earlier versions of this doc claimed the app-side
Series feature didn't exist yet ("no Swift model," "app-side work tracked in the design spec's own
phasing"). **That was wrong.** A direct check of the Nib app repo found the feature is fully built:
`Nib/Models/Series.swift` (Codable, exact schema match), `Nib/Repositories/FactRepository.loadSeries()`,
`Nib/Services/FactService.swift` (`allSeries()`, `facts(in:)`, `series(containing:)`,
`series(featuring:)`, and a `validate()` method that already checks series referential integrity —
there *is* an automated dangling-ref check, just app-side in Swift, not a pnpm script here),
`Nib/Services/FeaturedSeriesPicker.swift` (monthly rotation + "NEW" badge logic, mirroring
`FeaturedCollectionPicker`), `Nib/Features/Series/SeriesDetailView.swift` +
`FeaturedSeriesCard.swift`, and test coverage in `FeaturedSeriesPickerTests.swift` +
`FactServiceTests.swift`. `Series.swift`'s own doc comment says it plainly: *"The bundled `series.json`
is interim seed content ... pending new facts from the content pipeline ... Replacing it with finished
content needs no code change."* The only missing piece really was finished content — which is what this
session produced. **Lesson for next time: verify an "app-side, not built yet" claim against the actual
app repo before repeating it** — this assumption was carried forward across multiple doc edits today
without anyone checking.

What's still genuinely true: `export-facts.ts` does not know `series.json` exists (it's hand-maintained,
same as `collections.json`), and it's not yet in the CDN manifest — so it ships with the app bundle but
can't be updated over-the-air yet. Confirm both before assuming otherwise.

**What "part of the pipeline" means today, concretely:**
- It's a real file in `exports/`, checked into git, kept in sync with `approved-facts.csv` by hand.
- Every `factIds` entry must resolve against `approved-facts.csv` — check this manually after any fact
  removal/rewrite pass (the app's own `FactService.validate()` will also catch a dangling ref, but don't
  rely on that as the only check — verify before syncing, not after). This session found and fixed one
  pre-existing dangling reference this way (`terror-birds-before-land-bridge`, cut in an earlier
  wow-factor-audit pass with nobody syncing this file — a preview of exactly the failure mode to watch
  for).
- After editing, sync to the app the same way `facts.json`/`sources.json` are synced:
  `cp exports/series.json ../Nib/Nib/Data/`.

# Current state: three built Series

## 1. The Alien Island (Socotra)

**9 facts / 6 categories** (`strange-places`, `geography`, `ancient-creatures`, `languages`,
`ancient-civilizations`, `famous-trees-plants`).

Seed facts (existing before this Series work): `socotra-endemic-plants`, `socotra-reptiles-snails`,
`socotra-marine-diversity`, `islands-isolation-shapes-life`, `woolly-mammoths-late-islands`.

New facts drafted for this Series: `soqotri-language-no-alphabet` (the Soqotri language had no written
alphabet until a 2024 UNESCO workshop), `hoq-cave-ancient-graffiti` (traders from India, Ethiopia, and
Arabia left graffiti in the same cave), `dragons-blood-tree-fog-harvesting` (the tree's umbrella shape
harvests fog into groundwater), `dragons-blood-tree-umbrella-species` (half of Socotra's reptiles depend
on it).

**Dropped during sourcing:** a Cucumber Tree (*Dendrosicyos socotranus*) fact — the planned Live Science
source scraped to nothing but newsletter-signup boilerplate, no real article content. Not re-sourced;
the Series clears the bar comfortably without it. Worth revisiting if a stronger source turns up.

## 2. The City Vesuvius Stopped (Pompeii)

**11 facts / 6 categories** (`geography`, `famous-disasters`, `languages`, `technology`, `literature`,
`colors`).

Seed facts: `volcanoes-not-just-lava`, `pompeii-preserved-city`, `pompeii-vesuvius-burial`,
`pompeii-excavation-source`, `palindromes-ancient-wordplay`.

New facts: `herculaneum-scrolls-ai-unwrapped` + `herculaneum-scrolls-vesuvius-challenge-prize` (AI/particle
accelerators reading carbonized scrolls, and the $1.8M crowdsourced prize behind it), `pliny-younger-skipped-rescue`
(chose to keep studying instead of joining his uncle's fatal rescue mission), `pompeian-red-two-causes`
(black "damage" on frescoes sometimes isn't from the eruption at all), `mount-vesuvius-plinian-eruption-term`
+ `mount-vesuvius-population-risk` (the "Plinian" eruption term, and 800,000 people living on its slopes today).

**Dropped during drafting (curation rule 7, not a sourcing failure):** a second Pliny fact
(`pliny-younger-imperfect-account`, about the unreliability of his account) and a second Pompeian Red
fact (a Vitruvius quote about cinnabar's light sensitivity) were both drafted and passed the quality bar,
but were cut to stop Pliny the Younger from anchoring a third of the Series' new content, and to avoid
two facts with near-identical "ancient mystery, modern chemistry" structure back to back.

**Landmine, per this repo's existing de-dup log (`session-handoff.md`):** `physics/Sound` already owns
the Krakatoa "loudest sound" angle, and `geography/Volcanoes` + `languages/Palindromes` already own the
two Pompeii seed facts. Don't accidentally re-draft either.

## 3. The Successful Failure (Apollo 13)

**9 facts / 5 categories** (`space`, `engineering`, `technology`, `medicine`, `physics`) — entirely new
content; nothing in the library touched Apollo 13 specifically before this Series.

Facts: `apollo13-earth-horizon-navigation` (no working nav computer, so the crew aimed home using Earth's
visible edge), `apollo13-explosion-lifeboat` (15 minutes of power to evacuate to the lunar module),
`apollo13-houston-misquote` ("Houston, we've had a problem" — past tense, not the famous misquote),
`apollo13-mailbox-co2-fix` + `apollo13-mailbox-jettisoned-replica` (the duct-tape CO2 scrubber, and the
fact that the real one was jettisoned into space — even the museum replica later needed conservation),
`apollo-guidance-computer-rope-memory` (flight software hand-woven into "rope memory" by former textile
workers), `apollo13-haise-kidney-infection` (a real mid-flight medical emergency), and
`apollo13-reentry-blackout-87-seconds` + `apollo13-reentry-shallow-angle-cause` (the communications
blackout ran suspiciously long, and NASA never fully agreed on why).

**Dropped during drafting:** a Nixon-praises-ground-crew fact (`WEAK_PAYOFF` — a president praising people
after a successful rescue isn't a real twist) and an early technology-angle replacement fact about a Jim
Lovell software bug from Apollo 8 (kept for accuracy but didn't stand up next to the rest of the slate on
a "does this feel as strong as its neighbors" read — replaced by the re-entry blackout pair instead, which
also diversified the Series into a 5th category, `physics`).

**Landmine:** `history/Space Race` already owns Apollo 11 (`space-race-armstrong-aldrin`) and the Sputnik
scramble (`space-race-sputnik`); `space/Solar System` owns "only 24 humans have walked on the Moon"
(`solar-system-only-24-moonwalkers`); `sports/Golf` owns the Apollo 14 golf balls
(`golf-scotland-real-golf`); `mathematics/Logarithms` owns slide-rules-flew-Apollo
(`logarithms-multiplication-addition`). None of these touch Apollo 13, but stay off the general
Space-Race/Moon-landing angles already claimed there — every fact here is about the mission's own 142
hours, not the broader Apollo program.

### Why the third candidate changed (2026-07-30)

Two earlier candidates were proposed and dropped in the same session that picked Apollo 13 — recording
both so a future session doesn't repeat the search:

- **Antikythera Mechanism** — the original third candidate. Dropped on user judgment: its three best
  `mysteries`-topic angles (1901 discovery, the engraved instruction manual, 1,000-years-unmatched
  significance) were already mined, and the only fresh sources found for gap-closing topics were thin —
  the strongest available source for a "modern replicas" angle was a ~300-word Archaeology Magazine
  artifact piece, not enough to clear the bar this feature needs.
- **Chernobyl** — proposed next, with real seed content (`chernobyl-unit-four-explosion`,
  `chernobyl-pripyat-evacuation`, `chernobyl-sweden-detected-radiation`, 3 facts in `famous-disasters`) and
  strong new-topic sourcing already found (World Nuclear Association for the RBMK design flaw and the New

  Pompeii, which felt too close in tone. If a 4th Series is ever wanted, Chernobyl's sourcing work above is
  still valid and doesn't need to be redone.

# Why these three, and not others

A broad search was run across this session — not just the two originally-proposed candidates, but
roughly 90 additional named-subject keywords spanning places, natural phenomena, inventions, historical
events, and people (Antarctica, Chernobyl, Sahara, Everest, Stonehenge, Machu Picchu, the Black Death,
DNA, radio, earthquakes, Leonardo da Vinci, Marie Curie, and many more). Worth recording so a future
session doesn't repeat the search:

- **Most keyword hits were coincidental, not real subject clusters.** Pulling the actual fact bodies for
  "Everest" (6 hits), "the Black Death" (5 hits), "earthquake" (8 hits), and "DNA" (9 hits) showed the
  word merely appeared in unrelated facts (a size comparison, a Pied Piper legend, scattered engineering
  facts, ant/mammoth/explorer trivia) — not a coherent, draftable subject.
- **Black Holes** (10 facts, spans `astronomy`/`technology`/`physics`/`colors`) was seriously considered
  and rejected: 7 of the 10 are pure `astronomy` repeating the same "black holes are extreme" claim —
  it's really the existing Black Holes *Topic*, not a multidisciplinary Series.
- **Coffee** (16 facts, 5 categories) is disqualified on principle — `coffee` is already a Category, so
  it can't also be a Series subject without contradicting the feature's own definition.
- **Glaciers** (8 facts, mostly `geography`) reads as "too broad" — closer to a general phenomenon than
  one bounded, named subject, the same failure mode as "Nature" or "The Ocean."
- **Krakatoa** (4 genuinely on-subject facts across `famous-disasters` + `physics`, including a nice art
  angle — its ash may be behind the sky in Munch's *The Scream*) is a real, promising subject but was
  set aside as a 4th-place candidate for now: thinner than the three above even before counting gaps,
  and the volcanic-eruption territory already overlaps with Pompeii's Series. Worth revisiting if a 4th
  Series is wanted later.
- **The Bermuda Triangle** (already a `mysteries` topic, 3/3 facts) was considered and rejected: its three
  best angles (Flight 19, the methane/rogue-wave debunk, the "not actually more dangerous" debunk) are
  already used, and every fresh angle found just retold "it's overhyped" in a different category's
  clothing — the same trap that disqualified Black Holes.

# What to actually do with this (for a future 4th Series, or re-sourcing a dropped topic)

1. **Research each gap-closing topic** through the normal pipeline — `source-discovery-and-registry.md`
   for sourcing, same trust bar as any other fact (specialist institutions over Wikipedia/blogs, per the
   existing house rule). Verify a source actually scrapes to real content before drafting from it — this
   session lost one candidate topic (Socotra's Cucumber Tree) to a source that scraped to newsletter
   boilerplate.
2. **Draft into `approved-content/approved-facts.csv`** using the normal house style
   (`fact-writing-and-quality-guide.md`) — headline/body/summary/tags, same 4+ age-rating gate, same
   "up to 3 facts per topic, quality-gated" rule. **Run every draft through the same wow-factor-audit lens**
   as the rest of the library (`docs/archive/wow-factor-audit-report-2026-07-22.md` for the method) —
   don't assume a first draft clears the bar just because it's new. This session cut roughly a quarter of
   its first-draft facts on a second read (weak payoffs, an accuracy overreach, a headline that overclaimed
   its source, and one topic-concentration issue).
3. **Run the normal pipeline** (`normalize:tags → assign:themes → generate:related → export:facts`) once
   the new facts are approved — nothing about Series changes this part.
4. **Update `../exports/series.json`** — add the new Series object (or append `factIds` to an existing
   one), same shape as the three above. Manually verify every `factId` resolves against
   `approved-facts.csv` before syncing.
5. **Sync to the app**: `cp exports/{facts,categories,collections,sources,series}.json ../Nib/Nib/Data/`
   (only copy the files that actually changed). The app-side Series feature is fully built — model,
   repository, service, views, `FeaturedSeriesPicker`, tests — so this is the *only* remaining step; no
   Swift code changes needed. `series.json` is not yet in `export-facts.ts` or the CDN manifest, so it
   ships with the app bundle but can't be updated over-the-air — flag that to a Nib-repo session if
   over-the-air Series updates become a priority.
